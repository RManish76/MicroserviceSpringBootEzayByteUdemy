*1* Update in GatewayServer
    First we'll work on GatewayServer.

    Lets update the the pom for circuit breaker dependency.

    copy the eureka client past it and update as below.

    Note we are adding reactor-resilience4j as the GatewayServer is build on spring reactive model,
    hence we need to make usre we are mentioning the artifact id as spring-cloud-starter-circuitbreaker-reactor-resilience4j

    now like we added rewrite and addresponsefilter, similiarly we'll add one more filter which is for
    circuitBreaker.
            .circuitBreaker(config -> config.setName("accountsCircuitBreaker")) //the name accountsCircuitBreakfer is given by us and can be anything.
                    It is to identify for which api this circuitBreaker is.

    Now since we have circuitBreaker, we need to set some property related to it as well which we'll do in
    application.yml of GatewayServer

            resilience4j.circuitbreaker:
                configs:
                    default: #default means these properties for all circuit breaker inside the gatewayServer MS. If we want to set properties for any particular circuit breaker we can metion the name which we give in GatewayserverApplication.java in place of default.
                        slidingWindowSize: 10 #Monitor atleast 10 request before moving to open from close
                        permittedNumberOfCallsInHalfOpenState: 2 #max 2 calls allowed in HalfOpen State. Take decision to go back to open or close status based  on these 2 request beahivour
                        failureRateThreshold: 50 # if alteast 50% of request failed the circuit breaker can move from open status to close status.
                        waitDurationInOpenState: 10000 #10000milisec-->10s wait for 10s in open state then only move to Half_Open state

*3* Adding Fallback

    When issue is occuring we are througing runtime error response like service unavalaiable or gateway 
    timeout exception.
    In real business application throwing RuntimeExceptions to the client applications or to the UI
    applications is not a valid approach.
    So we'll add some fallback mechanism and inside this fallback mechanism we can write some logic
    where we can send some message to the client applications, which is going to make sense for them
    to create a fallback mechanism for circuit breaker pattern.

    we'll create a controller in gatewayServer MS with name FallbackController.java
    Inside this controller we created a rest endpoint /contactSupport which we want to trigger as fallback
    
    To call this against accountsCircuitBreaker we can add one more setup after .setName with .setFallbackUri()
    and pass the api link to it.
