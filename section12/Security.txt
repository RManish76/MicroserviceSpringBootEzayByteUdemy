We are going to implement IAM.
    IAM - OpenID Connect (OCID) + OAuth
        OCID - for id_token --> stores details of Resource owner(user). which is responsible for who are you?
        OAuth - for access_token --> stores the details of Authorization. what are you allowed to do?
                                        (what to allow to access other
                                        than profile detials like allow to access photos stored in google photos
                                        or allow to access the repo present in github repo account.)


Now to implement this we'll use KeyCloak to acheive the same. which will be responsible for generating the
    tokens and verifying the tokens.

    Gatewayserver will act as the service provider. Means any request which want to access any resource from
    our application will have to go thorugh the gatewayserver. And each request will have the id_token and
    access_token. Before provding the requested resource in the request the gatewayserver will reach to 
    KeyCloak to veirfy the resource and will provide the resource only once if tokens are vaild.

    Now the question is that its ok if request goes to gatewayserver but now in our case all MS endpoints
    are open to any one means anyone can trigger any rest endpoints of any MS without authentication or
    authorization.
    Yes but in real project all MS will be behind a firewall. And now can access anything which is inisde the
    firewall from outside of firewall. And the only entry point to firewall is available through the
    gatewayserver server. Hence no one will able to access any MS except with the gatewayserver endpoint.
    And also it means that we don't need to apply any authorization validation to any MS as all request will
    come thorugh only gatewayserver that request will be verified by gatewayserver and KeyCloak.

    You can also say that we apply the validation logic in all MS as well but it's bad practice also it'll
    make our MS to extra thing which it suposed it should not do. Also it'll send too many request to
    KeyCloak as one request can travel to multiple MS, and each MS will try to validate the request.

    Curretly the GatewayServer know which request it needs to authenticate and which not.
        But it does not know how to authenticate or validate.
        To do that we'll add a configuration in application.yml to tell spring to connect this for authentication.
            spring.security.oauth2.resourceserver.jwt.jwk-set-uri = "http://localhost:7080/realms/master/protocol/openid-connect/certs"

        The purpose of this path?
            During the statup of the resource server, it is going to connect with the resource server and it is going to
            download a public certificate from the KeyCloak server.
            purpose of this certificate?
                Using this public certificate, my resource server can validate if a given access token is really is used by
                the KeyCloak server.
                    If yes, is it a valid access token or an invalid access token?
                    So all those checks on the access token, it can perform with the help of this public certificate.
                The KeyCloak is going to have private certificates, Using the private certificates, the keycloak can only
                issue the new tokens, whereas with the help of this public certificate, any server like resource server can
                validate if a given access token is valid or not. They cannot really produce new tokens, but they should be able
                to validate if the given access token is valid or not.
