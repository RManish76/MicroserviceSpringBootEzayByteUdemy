*2* User Creation for kubernetes dashboard using helm

        Doc: https://github.com/kubernetes/dashboard/blob/master/docs/user/access-control/creating-sample-user.md

        As per do we need create a file with name dashboard-adminuser-yaml and past the following.
                    apiVersion: v1
                    kind: ServiceAccount  #ServiceAccount is a predefined object inside the Kubernetes, which tells what kind/type of user we want.
                    metadata:
                        name: admin-user #name/username of the ServiceAccount
                        namespace: kubernetes-dashboard #I don't know what namespace signify here, but not mentioned the user will be created under defual namespace. hence we are giving the custome to easy the identification.

            then we need to run the cmd ~ kubectl apply -f dashboard-adminuser.yaml
                kubectl -- is for kubernetes  like for docker we use docker in cmd and git for git in cmd.

            After running the command we'll get response as serviceaccount/admin-user created
        
        I have created a folder with KubernetesDashboard and store the file there.

    
        Creation of user completed but we need add privilages to the account which we created.
        Same thing we can see in the doc as well with section name as Creating a ClusterRoleBinding
            like earlier again we'll create file and paste the yaml code there and pass it kubernetes
            using same command, just update the file name.

                    apiVersion: rbac.authorization.k8s.io/v1
                    kind: ClusterRoleBinding #Again same what is kind/type of the following yaml
                    metadata: #details related to user
                        name: admin-user #name of the ClusterRoleBinding, like name this process. keepeing same as username/serviceaccount.
                    roleRef: #details related to role
                        apiGroup: rbac.authorization.k8s.io #the api of role
                        kind: ClusterRole #what kind/type/group of role it is.
                        name: cluster-admin # the role name which we want to assign to the user
                    subjects: #details to who the role is to be assigned
                    - kind: ServiceAccount #type of the user
                        name: admin-user #the username of the user/serviceaccount
                        namespace: kubernetes-dashboard #the namespace/group (like qa,prod etc) where the user is.

            cmd kubectl apply -f dashboard-rolebinding.yaml
            response clusterrolebinding.rbac.authorization.k8s.io/admin-user created
            created file with name dashboard-rolebinding.yaml and pasted theyaml and ran the command.



        Creation of user and assigning the privilages are done.
        Now we need to fetch the token using which we'll login to docker desktop as per the Doc.
            cmd kubectl -n kubernetes-dashboard create token admin-user
                    -n --> namespace

        After running the cmd we'll get the token use that to login to dashboard.

*4* Deployment of MS at kubernetes cluster
        To get stared with the deployment of our microservices.
        First, we need to give insturctions to the Kubernetes on how we want to deploy our MS and how
        we want to expose them.
        All these information we need to provide thenm in a yaml configuration.

        Whatever we have used with the help of Docker compose, we cannot simply give those to the
        Kubernetes because kubernetes cannot understand the format or syntax of the Docker compose,
        kubernetes has its own format.

        The 1st MS we are going to deploy in kubernetes is configserver(profile ms).

        Created new folder KubernetesMicroservices and inside that folder created a file with name
        configserver.yaml
        copied the yaml and pasted in the file from the instructor repo. Also we can find the similar
        insturctions in Doc of kubernetes 
            https://kubernetes.io/docs/concepts/workloads/controllers/deployment/

            https://kubernetes.io/docs/tasks/run-application/run-stateless-application-deployment/

        I have add neccessary comments in the yaml file.
        these kubernetes configuration file also known as kubernetes manifest files, and this is
        industry standard. So we should always call them as Kubernetes manifest files.

        We can run below cmd to get existing deployments.

            cmd:    kubectl get deployments         this command will show all deployments
            cmd:    kubectl get services            this command will show all the services
            cmd:    kubectl get replicaset          this command will show all the replica
            cmd:    kubectl get Pods                this command will show all the pods running

        Now we'll deploy the configserver using manifest file we have created. open cmd where the manifest
        file is there and open cmd and run below commands
            cmd:    kubectl apply -f configserver.yaml          this command will create the service and deployment

        now after running the apply command we run above get commmand to see the details.
        or we can goto kubernetes dashboard to see the details.
        like sercives, replica And pods.
        Inside the pods option we'll see the pod running for configserver, we can go inside then click
        on 4line / log button to see the springboot logs.

        now lets see we see the profiles with api links.
            http://localhost:8071/accounts/prod      (success showed both prod and defaul as per expected)
            http://localhost:8071/loans/prod        (success showed both prod and defaul as per expected)
            http://localhost:8071/eurekaserver/default     as eurekaserver only single profile.  (success)


*5* Environment variable in Kubernetes cluster

        Eariler in docker-compose file we used to pass a lot of environment variables from the docker-compose file
        for example, what profile need to activate - prod, qa or default. url of configserver, url of eureakserver etc.

        All all of our MS need these environment variables to get started. We need to look for an option on how
        to create the same kind of environment varibles inside the kubernetes cluster as well.

        For the same, we are going to create an object of configmap inside kubernetes.
        Doc: https://kubernetes.io/docs/concepts/configuration/configmap/
        as per the doc: A ConfigMap is an API object used to store non-confidential data in key-value pairs.
                        Pods can consume ConfigMaps as environment variables, command-line arguments, or as configuration files in a volume.
        
        In the doc we can see the syntax of kubernetes manifest file for this configmap for our environment variables
        we'll use the same.

        Like configmap we also have secrets manifest option if we see in doc at left index bar. we can use for confidential things.

        Let's focus on configmap.
            Created a file with name configmap.yaml in same folder KubernetesMicroservices.
            And copy pasted the yaml for instructor repo. will put comments in yml for better understanding.

            Again after done which file need run the command to apply the manifest file.
                cmd: kubectl apply -f configmaps.yaml
            After running the command we can goto kubernetes dashboard and goto configmaps from left side index bar.
            and we'll a option with name ezaybank-configmap which we provided in yaml file.
            and inside that we'll able to see all the environment variables.
