*2* User Creation for kubernetes dashboard using helm

        Doc: https://github.com/kubernetes/dashboard/blob/master/docs/user/access-control/creating-sample-user.md

        As per do we need create a file with name dashboard-adminuser-yaml and past the following.
                    apiVersion: v1
                    kind: ServiceAccount  #ServiceAccount is a predefined object inside the Kubernetes, which tells what kind/type of user we want.
                    metadata:
                        name: admin-user #name/username of the ServiceAccount
                        namespace: kubernetes-dashboard #I don't know what namespace signify here, but not mentioned the user will be created under defual namespace. hence we are giving the custome to easy the identification.

            then we need to run the cmd ~ kubectl apply -f dashboard-adminuser.yaml
                kubectl -- is for kubernetes  like for docker we use docker in cmd and git for git in cmd.

            After running the command we'll get response as serviceaccount/admin-user created
        
        I have created a folder with KubernetesDashboard and store the file there.

    
        Creation of user completed but we need add privilages to the account which we created.
        Same thing we can see in the doc as well with section name as Creating a ClusterRoleBinding
            like earlier again we'll create file and paste the yaml code there and pass it kubernetes
            using same command, just update the file name.

                    apiVersion: rbac.authorization.k8s.io/v1
                    kind: ClusterRoleBinding #Again same what is kind/type of the following yaml
                    metadata: #details related to user
                        name: admin-user #name of the ClusterRoleBinding, like name this process. keepeing same as username/serviceaccount.
                    roleRef: #details related to role
                        apiGroup: rbac.authorization.k8s.io #the api of role
                        kind: ClusterRole #what kind/type/group of role it is.
                        name: cluster-admin # the role name which we want to assign to the user
                    subjects: #details to who the role is to be assigned
                    - kind: ServiceAccount #type of the user
                        name: admin-user #the username of the user/serviceaccount
                        namespace: kubernetes-dashboard #the namespace/group (like qa,prod etc) where the user is.

            cmd kubectl apply -f dashboard-rolebinding.yaml
            response clusterrolebinding.rbac.authorization.k8s.io/admin-user created
            created file with name dashboard-rolebinding.yaml and pasted theyaml and ran the command.



        Creation of user and assigning the privilages are done.
        Now we need to fetch the token using which we'll login to docker desktop as per the Doc.
            cmd kubectl -n kubernetes-dashboard create token admin-user
                    -n --> namespace

        After running the cmd we'll get the token use that to login to dashboard.

*8* update the container with latest container and rollback to pervious cotainer.

        we'll try to migrate to the another container from current container like currently running
        s12, we'll migrate to s11 think of it as new relase.
        Then we'll also see how to rollback to s12 previous state from s11 like stimulating new relase has
        some issue need to to fallback to pervious version.

        1st upgarade
        cmd: kubectl set image deployment gatewayserver-deployment gatewayserver=eazybytes/gatewayserver:s11 --record

        After running the above command, kubernetes will first try to pull the image and start the container
        only after this it'll start terminating the previous running container.
        While pulling or strating new container if any issue occured kubernetes will stop there and will not
        initate the termination of previous running container.

        2nd rollback

        we need to run the command
            kubectl rollout history deployment gatewayserver-deployment
        
        Above command will show all rollout happened upgrade, downgrade, error rollout etc.
        We can see two column, 1st Revision (shows serial number) and 2nd is change-cause (shows command/cause of rollout)
        we can run the following to command to rollback as per the serial number. we put the serial number at command at which we want to rollback
            cmd: kubectl rollout undo deployment gatewayserver-deployment --to-revision=1           here 1 is the revision serial number
