By default Kubernetes does not have service registery, service discovery and loadbalancing, we need to configure that.
In spring cloud, we have project with name spring cloud Kubernetes which will help us to setup the all.
        Doc: https://spring.io/projects/spring-cloud-kubernetes#overview
        
        Insturctor is using this blog for setup: https://spring.io/blog/2021/10/26/new-features-for-spring-cloud-kubernetes-in-spring-cloud-2021-0-0-m3

*1* setup
        Copy the mainfest file place inside a file from the blog.
        pasted at kubernetes/kubernetes-discoveryserver.yml

        Also updating the yml file and yml file is old its not working properly, hence some modification is needed.

        #whenever kind as list mentioned means we create any number of kubernetes objects under the items section.

        # the lattest image tag we can check in docker hub at springcloud/spring-cloud-kuberbetes-discoveryserver

        by default the kubernetes will check the health after start of pod in 10 or 20 sec and if not started then
        it'll restart the pod. And if systemis slow then this will continue like infinte loop unitll retry limit hit.
        Hence provided 100sec as time, which tells that only test for health and liveness after 100 sec of start of container
        and then if not got true response then restat.

        Also added a time of 30 sec. As once pod started successfully, the kuberbetes is going to monitor it health and
        liveness and for that by default it'll probe every 5 or 10 sec. hence provided 30sec, which means i asking
        do the health and liveness check with 30 sec interval.

        now since the mainfest file is ready we can setup the discovery server.

*2*     Setup discovery server
                Before setting up, we may think that why here we are not using helm.
                        there are two reasons on why we are using helm 
                        1st is that Discovery Server is a one time setup inside the kubernetes cluster. And we don't
                                have to do multiple changes every time. with that reason, manually running these
                                mainfest files should be fine becuse this is only one time activity.
                        2nd is reason is as of now there is no helm chart developed by the helm chart community, including
                                Bitnami for these discovery server.
                                So if we try to integrate these manifest file into our eazybank helm chart, then it is
                                going to need a lot of efforest which I felt like it is not worth since this is only
                                going to be one time activity.

        As we know the command to apply the mainfest, we'll use the same.
                d:/../section17/kubernetes> kubectl apply -f kubernetes-discoveryserver.yml
