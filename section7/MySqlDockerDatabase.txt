*2* Install and run the mySQL docker

    >> docker run -p 3306:3306 --name accountsdb -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=accountsdb -d mysql

    3306 --> default port of mySQL
    --name --> name of the container which we want. else random name will be assigned by docker
    -e --> saying next element is enviorment variable
    MYSQL_ROOT_PASSWORD --> root password of the database. we have give root as pasword and username is root by default
    MYSQL_DATABASE  --> by default when we install any database, it does not have any schema/server installed.
                        we want to create a schema/server in database and the name is accountsdb
    -d --> to run the docker in detached mode
    mysql --> the name of the image which we want to download

    similary we created the container for loans at port 3307 and cards at port 3308
    >> docker run -p 3307:3306 --name loansdb -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=loansdb -d mysql
    >> docker run -p 3308:3306 --name cardsdb -e MYSQL_ROOT_PASSWORD=root -e MYSQL_DATABASE=cardsdb -d mysql

*6* Not able to connect with loans and cards database.
        the accounts service was able to connect to accountsdb but the loans and cards service
        was not able to connect their respective database container.

        Its because for loans and cards we have given port as 3307 and 3308.
        When one container tries to connect with another container on same network then it
        does not goes outside of docker to connect it internally tries to connect.
        And we know that internally the loans and cards database are running on 3306 port.
        and but in configuration we are asking to look for 3307 and 3308 port hence the
        MS services not able to find the database.
        where as since for account we have given the port 3306 it is able to find the accountsdb.

        then why we are exposing the loansdb and cardsdb thorugh 3307 and 3308 port.
        Its because we want connect the database externally through the client to 
        check the data there.

        after making the changes. we ran docker compose up -d and all containers working fine.
