*5* Communication between MS
    We are going to create a new rest endpoint in accounts MS.
    which going to consolidate the details of cards and loans MS for a particualr customer on request.

    --> Added OpenFeign dependency in accounts pom file.
        this dependency will help us to do Communication between MS more easily
        else we can follow RestTemplate to make Communication which is a mannual task.
        The OpenFeign is like JPA. like in case of query we did not write any implementation code(query/code).
        Using JPA we only written declarative code (findByCustomerId etc)in a interface, and beind the scene the JPA will
        generate implementation code for us at run time.
        similarlly using OpenFeign we only need to write the declarative code(abstract) in an interface for calling
        other MS restendpoint and behind the scene OpenFeign will do the implementation code.


        After adding feign dependency we go to AccountsApplication.java and add
        @EnableFeignClient annotation to the class.
        This annotation will enable functionality realted feign, with that account MS
        will able to connect to other MS.

        Now lets create a folder under service folder with name client and inside the client
        folder we are going to create an interface as CardsFeignClient.java to connect with Cards MS
        To use the OpenFeign library we need annotat the interface with @FeignClient.
        and inside this annotation we need to add the MS name which we have registered in eureakServer.
        and that was cards only. so the annotation will be
            @FeignClient("cards")
        So the feign client will connect with the Eureka server at the runtime and it will try to get all
        the instance details with the logical name cards.

        After the annotation we are going to define the abstract method. we can copy the rest method and
        put it here from cards MS. we need fetch request method here. After doing it, it'll look like below.

                @FeignClient("cards")
                public interface CardsFeignClient {
                    @GetMapping(value = "/api/fetch", consumes = "application/json")
                    public ResponseEntity<CardsDto> fetchCardDetails(@RequestParam String mobileNumber);
                }
            Notice we have kept the restendpoint as well and its same and have to same what we have in cardsMS.
            Also we have added consumes to tell what to of datastructure will this rest endpoint will use.
            the method name we can keep any thing but the method signature like response type, request type should
            be as it was in cardsMS.
            we removed the validation code from the method as validation will be performed at REST api level not here.
            But if notice it need the CardsDto, so we need to create the CardsDto in accountsMS as well.
            So copied the CardsDto from cardsMS and pasted in accountsMS in dto folder.
            Also copied the LoansDto from LoansMS and pasted in accountsMS in dto folder as we would nedd that as
            well, as we are going to fetch details realted to loan as well.


        So behid the scenes, the cards FeignClient will connect with EurekaServer and try to fetch all the instances
        that are registered with the logical name cards.
        And once it receives 1 0t 2 or any ohter instances details, it will try to cache those details for 30s,
        which is default period, And within these 30s it is not going to connect again with the EurekaServer, but instead
        it going to leverage the details present inside the cache.
        So based upon the IP details inside the cache, it is going to invoke this API along with the request
        which is mobile number.
